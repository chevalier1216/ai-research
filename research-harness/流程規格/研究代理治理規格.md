# 研究代理治理規格

<!-- governance: specification -->

## 適用範圍

適用於生鮮食材市場、醫療資源分配與到府服務，以及後續消費者 AI 商機研究。此規格只管流程、代理與交接；不判斷任何研究報告的結論。

## 問題定義

先前流程會把審核缺口直接轉為新代理、新階段與新交接。這使研究角色從必要的獨立驗證，膨脹為無上限的補證鏈，重複傳遞內容並增加 token、等待時間與上下文漂移風險。

## 固定五階段

1. **命題與分工**：協調者用 `grill-me` 逐一確認命題、邊界、驗收條件與是否需要平行蒐證。產物是研究計畫與工作包；不是子代理。
2. **證據蒐集**：預設一個蒐集角色。只有臺灣與海外來源集合可獨立、同時交付相同證據欄位、且可縮短關鍵路徑時，才使用兩個蒐集角色。最大值為兩個。
3. **來源驗證**：一個驗證角色檢查每個核心主張的原始來源、位置、日期、適用範圍與衝突。
4. **分析整合**：一個分析角色只讀已驗證主張 ID 與必要限制，萃取競品差異、消費者摩擦與可反駁的商機假說。
5. **審核與編輯**：審核角色先依驗收條件判定前進、補證或停止；只有前進時，獨立編輯角色依模板產製報告與 4W。

協調者不把「需要一個新問題的答案」當作新增代理理由。角色切換只發生在固定階段邊界。

## 代理啟動閘門

每個新增蒐集角色必須同時符合下列六項，並記入研究計畫：

1. 工作包與其他來源集合互不相依。
2. 指定輸出檔案、來源欄位與證據 ID 規則。
3. 指定可驗收條件。
4. 說明其相對於既有角色可縮短的關鍵路徑。
5. 記錄既有角色無法完成的原因。
6. 資料及工具安全範圍：不會存取已登入服務、敏感資料或未核准的外部工具。

任一項不符合時，既有蒐集角色依序處理。不得遞迴派生子代理，也不得為摘要、格式化、單一 URL、單一問題或審核意見新增代理。

## 交接與 token 節制

- 使用 `templates/handoff.md`；結論上限 500 字，主張／證據對最多 12 組，風險與缺口各最多 3 項。
- 下游以 ID 讀取所需上游檔案，不接收原始摘錄、搜尋軌跡或思考過程。
- `caveman` 僅壓縮交接與實際案例 4W 概要的敘述。研究檔、來源摘錄與報告仍以正常、可稽核中文撰寫；4W 不得成為研究作業日誌。
- 交接若無新增主張、狀態或缺口，不建立新交接檔；在既有批次紀錄補上版本即可。

## 審核、補證與停止

審核角色只能選擇：

| 判定 | 條件 | 行動 |
|---|---|---|
| 前進 | 核心主張均可追溯，限制已揭露 | 交給編輯產製報告 |
| 單次補證 | 最多三個、且會影響核心主張的具體缺口 | 建立 `rework-register.md`，交回原角色一次 |
| 停止並請示 | 補證後仍缺關鍵證據、兩次嘗試無實質進展、或將改變範圍 | 說明阻礙、已嘗試方法與最小決策 |

補證完成後直接回到同一審核角色。不得新增「補證審核」、「再審核」、「重整分析」或同義的新階段。

## 技能使用矩陣

| 技能 | 使用時機 | 不得用於 |
|---|---|---|
| `grill-me` | 命題開始、範圍變更；一次只確認一項決策 | 每個證據缺口、替代審核 |
| `caveman` | 交接、4W、工作狀態壓縮 | 正式報告、證據判讀、來源驗證 |
| `ai-research-harness` | 研究分段、來源可追溯、跨市場競品規則 | 無上限代理調度 |
| `superpowers:using-superpowers` | 每次工作開始時確認適用技能與其限制 | 取代研究證據規格、來源驗證或醫療責任邊界 |
| `superpowers:writing-plans` | 命題經確認後，將研究範圍、驗收條件、工作包與交接寫入研究計畫 | 未經命題與邊界定義就直接寫產品方案 |
| `superpowers:dispatching-parallel-agents` | 兩個以上相互獨立的蒐證工作包，且每個工作包均通過代理啟動閘門 | 串行驗證、補證、摘要、格式化或同一來源的重複搜尋 |
| `superpowers:using-git-worktrees` | 兩個研究分支或實作分支需要隔離檔案狀態時 | 以工作目錄取代來源或結論交接 |
| `superpowers:systematic-debugging` | 檢查腳本、工具、來源擷取或自動化出現非預期失敗時，先記錄事實再修正 | 將資料不足、來源衝突或研究範圍變更誤判為技術故障 |
| `superpowers:verification-before-completion` | 報告聲稱完成、建立提交或推送前，執行可重現的規則、格式與來源檢查 | 以測試通過宣稱未驗證的市場需求、療效或商業成果 |
| 平行代理技能 | 通過代理啟動閘門後的獨立蒐證 | 序列工作、補證、摘要或格式化 |
| `find-skills` | 確認既有技能無法完成的明確缺口 | 研究執行途中臨時蒐集工具 |
| `slidecraft`、`HyperFrames`、AEM `content-distribution` | 經核准的呈現或 AEM 發布工作 | 研究證據、分析或代理調度 |

`superpowers:brainstorming`、`test-driven-development`、`executing-plans`、程式碼審核與分支收尾等開發技能，不在市場研究階段使用。只有當本研究找到核心需求、形成策劃規格，且經使用者確認要交付 GitHub 專案時，才依其原有順序啟用；仍須遵守本規格的工作包、交接與驗證限制。

## 執行前檢查

執行 `research-harness/scripts/verify-research-governance.ps1`。檢查失敗時不得啟動新一輪研究；先修正流程資產或在研究計畫中記錄經使用者核准的例外。
