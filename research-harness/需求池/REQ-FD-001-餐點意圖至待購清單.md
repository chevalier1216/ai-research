# REQ-FD-001｜餐點意圖至待購清單

## 基本資料

| 欄位 | 內容 |
|---|---|
| 狀態 | 待人工確認 |
| 類型 | 需求驗證規格 |
| 目標市場 | 臺灣；需規劃家庭餐食並自行採購生鮮食材的消費者 |
| 來源階段 | 04 分析整合、05 獨立審核、05 階段交接 |
| 決策用途 | 決定是否進入使用者需求與落地依賴驗證 |
| 非決策用途 | 不作開發排程、營收估算、商業化判定、合作承諾或系統串接授權 |

## 問題敘述

**待驗證：** 目標使用者在規劃家庭餐食與自行採購生鮮食材時，可能因餐點決策、食譜食材整併、包裝規格換算、既有存貨與待購提醒而耗費時間、發生遺漏或購買不符需求。現有資料沒有臺灣使用者行為、訪談、交易或付費證據；此敘述不是已確認需求。

## 假設的使用者流程

1. 使用者以自然語言輸入用餐期待。
2. 系統產生**可修改**的餐點計畫、食材種類與數量。
3. 使用者可提供或修改既有存貨與包裝規格，並核對清單中的遺漏、重複或不適用項目。
4. 使用者明確確認後，才建立待購清單或購物車草稿。
5. 使用者自行完成最後購買確認；本規格不包含自動下單。

## 待驗證需求與判準

| ID | 待驗證敘述 | 驗證方式 | 預先設定的否決／重寫條件 |
|---|---|---|---|
| H1 | 可修改餐點計畫與待購清單可降低採購規劃摩擦。 | 以相同餐食任務比較現有自助規劃與可修改原型；觀察完成率、完成時間、修改次數與任務後訪談。 | 未改善預先定義的任務表現，或受測者不認為問題重要。 |
| H2 | 納入存貨與包裝規格的清單可減少遺漏、重複或不適用項目。 | 以真實或模擬的一週餐食任務，請受測者核對清單。 | 核對結果未顯示清單品質改善。 |
| H3 | 確認後才建立待購清單／購物車草稿，可維持控制感。 | 原型明示資料用途、價格與配送未知或變動處，並觀察理解與接受程度。 | 受測者無法辨識訂單、價格或配送責任。 |

## 需求邊界與限制

- 使用者必須可修改、刪除或拒絕任何餐點、食材、數量與待購結果。
- 使用者確認是建立待購清單或購物車草稿的必要控制點；不得自動下單。
- 價格、庫存、配送範圍、到貨時間與包裝規格均視為可能變動；未取得可驗證資料前，不可呈現為可靠結果。
- 個人化若使用餐食偏好、既有存貨、瀏覽或服務使用資料，需先查驗資料用途、同意、退出、政策版本與實際資料流。
- 不提供醫療或營養診斷。
