# 雙主題研究執行計畫

> **供 agent 執行：** 必須按任務順序交付階段結論。不得把搜尋過程、逐字推理或未驗證結論帶入下一任務。

**目標：** 產出兩份可稽核的臺灣 AI 消費服務商機研究報告，並只將通過審核的需求候選寫入需求池。

**全域限制：** 全中文；事實、推論、建議分開；來源置於報告最後；醫療題目僅研究服務分流與合規邊界；未經人工確認不得交付實作 agent。

### 任務 1：建立兩條研究線的階段檔案

**建立：** `research-harness/研究作業/2026-08-04/食材電商/`、`research-harness/研究作業/2026-08-04/就醫服務/`。

- [ ] 寫入各自主題的 01 命題定義與交接結論。
- [ ] 建立 02 至 06 的空白交接檔案，欄位僅含結論、來源 ID、限制、下一步與停止條件。
- [ ] 驗證兩條研究線沒有共用草稿或未標記來源。

### 任務 2：食材電商證據蒐集與驗證

**輸入：** 食材電商的 01 交接結論。

- [ ] 優先查找愛上新鮮公開服務資料、臺灣官方資料、可比較的第一手業者案例。
- [ ] 為每個主張記錄原始網址、出版者、日期、支持位置與限制。
- [ ] 僅把通過驗證的主張交給分析階段。

### 任務 3：就醫服務證據蒐集與驗證

**輸入：** 就醫服務的 01 交接結論。

- [ ] 優先查找臺灣衛生主管機關、健保署、法規與可比較業者第一手資料。
- [ ] 將遠距醫療、分級醫療、到府檢測與緊急轉介的合規邊界分開記錄。
- [ ] 僅把通過驗證的主張交給分析階段。

### 任務 4：分析、獨立審核與交付

**輸入：** 各研究線的 03 交接結論。

- [ ] 分析核心消費者需求、未滿足摩擦與可測試產品假說。
- [ ] 審核每項需求是否由已驗證資料支持，並自動提出下一步研究方向。
- [ ] 只為通過審核的候選建立「待人工確認」需求規格；不可產出實作交付檔。
- [ ] 產出報告與 4W 進度，最後章節固定為「已驗證資料來源」。
